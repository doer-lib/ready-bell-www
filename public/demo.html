Two small services built on ready-bell. In the first, the backend sends the notification when a slow job finishes. In the second, the backend waits for a notification from an AWS Lambda. Every button below calls the real API at https://demo.ready-bell.com.

1. hello-async: the backend sends Notify

Start a job that pretends to work for a few seconds. When it finishes, the backend sends Notify <uuid> to ready-bell, and your terminal, listening on the same uuid, receives Ready <uuid>. That is the moment to fetch the result.

  1. Pick a uuid

  2. Listen for it in a terminal

    Start nc in a terminal, then paste the Listen line and press Enter. nc prints Registered … right away, then Ready … when the job below finishes. The subscription lasts 120 seconds.

    nc -u ready-bell.com 3137

2. hello-cloud: the backend waits for Ready

        

          The work runs in AWS. You upload input.txt straight to S3, which triggers a
          Lambda that writes output.txt and sends Notify <uuid>.
          The backend listens on the uuid, so the Ready makes it check S3 right away
          instead of at its next 10-second poll. The event stream shows what the backend does.
